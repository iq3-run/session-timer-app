# 実装計画: セッションの流れの個別「適用」ボタン

Issue: #94（親: #1）

## 要件（issue本文）

セッションの流れの個別の流れに「適用」ボタンをつけ、任意の時間を適用する。

- 開始時刻の扱い
  - 現在時刻が開始時刻より前: そのまま適用
  - 現在時刻が開始時刻以降だが終了時刻より前: 過去の時刻として適用（残り○分がマイナス）
  - 現在時刻が終了時刻より後: 翌日として適用
- 終了時刻の扱い
  - 現在時刻が終了時刻より前: そのまま適用
  - 現在時刻が終了時刻以降: 翌日として適用

「日付情報も持っている？」という疑問は、セッションを日付なしの時刻のみで保持する変更（PR #98）で
解決済み。

## 方針

既存の「現在のセッションを設定」（`resolveCurrentSession`）は、現在進行中または次に始まる
セッションを自動で1件選び、完了時刻と指定時刻に反映する。これに加えて、**任意の1行を指定して**
同じ2か所に反映できるようにする。

### 日時の決め方

各セッションについて「終了が現在より後になる最初の発生」を求める
（`resolveCurrentSession`が内部で使っていた`_currentOrNextOccurrence`を
`resolveSessionOccurrence`として公開し、再利用する）。

- 終了: その発生の終了日時（今日の終了がまだ先なら今日、過ぎていれば翌日）
- 開始: 同じ発生の開始日時。進行中なら現在より前の時刻になる（残りがマイナス）。
  終了が過ぎていれば翌日の開始日時

issueの表のとおりになる。開始を「今日の日付」ではなく終了から導くので、日跨ぎセッション
（23:00〜2:00）を深夜1時に適用しても、開始は昨日の23:00・終了は今日の2:00と正しく扱える。

### `lib/features/session_plan/session_plan_screen.dart`

- 各行に「適用」ボタンを追加（行は`[時刻ラベル][適用][✕]`）。最小タップ領域は48×48
  （#90の✕ボタンと同じ考え方。行全体の「タップで編集」と領域が重ならないよう、`Row`の兄弟として置く）
- 押すと、完了時刻に終了日時、指定時刻（自動管理の1件`session-plan:auto`）に開始日時を設定する。
  指定時刻のタイトルは「セッション開始」（過去の時刻にもなり得るため、「次の」は付けない）
- 反映先の書き込みは「現在のセッションを設定」と共通化する（`_applyTimes`）
- 反映後に「H:mm〜H:mm を適用しました」を表示する。確認ダイアログは出さない
  （既存の「現在のセッションを設定」と同じ。完了時刻と指定時刻の上書きのみで、元に戻せる）

## 既存の挙動との関係

- 指定時刻が過去になる場合（進行中のセッションを適用したとき）は、アプリを再起動すると
  `TimeTargetsController`の既存仕様（期限切れの指定時刻は起動時に削除）で消える。
  issueの「残り○分がマイナス」は、起動中の表示として満たす
- 「現在のセッションを設定」の挙動は変更しない

## 実装しないこと

- 完了時刻・指定時刻を個別に選んで適用する（常に両方を設定する）
- 適用前の確認ダイアログ
- 適用済みの行の強調表示

## テスト

- `current_session_resolution_test.dart`: 開始前／進行中（開始が過去）／開始ちょうど／終了ちょうど（翌日）／
  終了後（翌日）、日跨ぎ（夜・深夜・終了ちょうど）、24時間セッション
- `session_plan_screen_test.dart`: 適用ボタンで完了時刻と指定時刻が設定されること
  （開始前・進行中・終了後）／他の行が変わらず編集ピッカーも開かないこと／
  2行目を適用すると指定時刻が増えず置き換わること

## 動作確認方法

`dart format` / `flutter analyze` / `flutter test`、デバッグビルド。
実機/エミュレータでは縦・横の両方で、行の「適用」ボタンと✕ボタンの配置・押しやすさを確認する。
