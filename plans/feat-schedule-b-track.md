# 実装計画: セッションスケジュールのA日程・B日程

Issue: #96（親: #1）

## 要件（issue本文）

1WE、1WDがA日程、B日程の2つがある場合がある。2WEから合流。

## 決めたこと（2026-11-27 JST、ユーザーとの事前確認）

| 項目 | 決定 |
| --- | --- |
| A/B を持てる種別 | **WE と WD のみ**。OR・CR・SS・CS は常に共通 |
| 表示 | **別の行**にして日付順。ラベルは「1WE(A)」「1WE(B)」 |
| 各日程の「週末間」 | **同じ日程の直前のイベント**から計算する（A と B を混ぜた日付順では計算しない） |
| 合流点（2WE）の「週末間」 | A・B**両方を併記**し、改行して表示する（例: `A:20日(3W)` / `B:13日(2W)`） |

## 変更内容

### `lib/features/schedule/session_event.dart`

- `SessionTrack { common, a, b }` を追加。`SessionEvent.track`（既定は`common`）。
  `SessionEvent.supportsTrack(type)`はWE/WDのみ`true`
- JSON: `track`は`common`のとき出力しない（`visible`と同じ方針で、A/Bを使わない場合の保存形式は
  変わらない）。キーがなければ`common`（A/B導入前の保存データがそのまま読める）。
  未知の値・文字列以外・WE/WD以外への指定は、その1件を破棄する
- `SessionEventController.addEvent`に`track`を追加。WE/WD以外は呼び出し側が何を渡しても
  `common`にする。既存の`setVisible` / `setManualNumber` / `setDate`は`track`を引き継ぐ

### `lib/features/schedule/session_event_numbering.dart`

番号を日程ごとに数える。

- A・Bの各イベント: その日程の番号 = 自分より前の**共通**イベント数 + 同じ日程の前のイベント数 + 1。
  1WE(A)と1WE(B)は、どちらも1WEになる
- 共通イベント（合流後）: 自分より前の共通イベント数 + **A・Bのうち進んでいる方**の数 + 1。
  A・Bの1WEの後の共通は2WEになる
- A/Bがなければ、従来の日付順の通し番号と同じ

「最初のWEは3日間、2番目以降は2日間」の判定は、この番号が1かどうかで行うため、1WE(A)・1WE(B)は
どちらも3日間になる（変更不要）。

### `lib/features/schedule/session_chain.dart`

- A・B**両方**にイベントがあるときだけ、日程ごとの計算にする（片方だけ、またはなしのときは、
  従来どおり1本のチェーン）
- A・Bのイベント: 共通イベントと**同じ日程**のイベントのうち、直前のものから日数を求める
- 共通イベント: A側・B側それぞれの直前のイベントから求める。直前が同じイベント、または
  片方しかなければ1つの値、異なれば2つの値（`ScheduleRow.trackChainGaps`）
- `ScheduleRow`に`trackChainGaps`を追加（合流行だけ非空。その行の`chainGap`は`null`）。
  「今日から」は日程に依存しないため変更なし
- `sessionEventLabel`: A/Bのとき`(A)` / `(B)`を付ける

### `lib/features/schedule/session_schedule_formatting.dart`

`formatChainGap(row)`: 通常は`formatGap(row.chainGap)`。合流行は`A:…`と`B:…`を改行でつなぐ。
読み取り専用のスケジュール画面と、ホーム画面ウィジェットへの送信の両方がこれを使う。

### `lib/features/schedule/session_schedule_settings_screen.dart`

追加フォームに「日程: 共通／A／B」の選択（`SegmentedButton`）を追加する。

- WE・WDを選んでいるときだけ表示。それ以外の種別に切り替えると、選択は共通に戻る
- 1行目（番号・種別・日付・追加）が狭い縦画面でも埋まるため、**別の行**に置く
- 追加のたびに「共通」に戻す（日付・番号を空に戻すのと同じ。選び忘れが次のイベントに
  黙って残るのを防ぐ）

## 実装しないこと

- 登録済みイベントのA/B・共通の**後からの変更**（誤って登録したときは、削除して追加し直す）。
  番号の手動上書き（`manualNumber`）と同じダイアログへの統合は、必要になったら別issueにする
- OR・CR・SS・CSへのA/B
- 合流行のA・Bの値のうち、どちらを「主」とするか（両方を併記するため不要）

## ホーム画面ウィジェット

`syncSchedule`は`formatChainGap`の結果をそのまま送る。ウィジェットの`item_chain_gap`は
`wrap_content`で行数の制限がなく、改行を含む文字列は2行で表示される想定（行が伸びるのは合流行だけ）。
ラベル（`1WE(A)`など）は従来より長くなる。Kotlin / XML は変更しない。

## テスト

- モデル: 既定は共通／WE・WDのみ対応／JSONの往復・共通は出力しない・旧データは共通／不正値と
  WE・WD以外への指定は破棄
- 番号付け: A・Bとも1WE／合流後は2WE・3WE／WEとWDは独立／日程で数が違うときは進んでいる方に続く／
  分岐前の共通が両方に数えられる／A/Bなしは従来どおり
- 間隔計算（`buildScheduleRows`）: ラベル／日付順／各日程が自分の直前から（1WE(B)はORから、
  1WD(A)は1WE(A)から）／合流行が2つの値（A:20日(3W)・B:13日(2W)）／合流後は1本に戻る／
  片方だけのときは従来どおり／A/Bなしは変化なし／「今日から」は日程に依存しない
- 整形（`formatChainGap`）: 単一・空欄・改行つきの2行
- コントローラー: `track`の保存と永続化／WE/WD以外では無視／編集で保持／旧データの読み込み
- 設定画面: 選択はWE・WDにだけ表示／既定は共通／A・Bで登録／追加後に共通へ戻る／種別変更で破棄／
  一覧のラベル／360px幅の縦画面でオーバーフローしない
- スケジュール画面・ウィジェット同期: 別行のラベルと、合流行の2行表示

`dart format` / `flutter analyze` / `flutter test`、デバッグビルド。
実機/エミュレータでは縦・横の両方で次を確認する。

- セッションスケジュール画面: 合流行の2行表示で行が見切れない
- ホーム画面ウィジェット: 合流行が2行で表示され、列がずれない・見切れない
